# Native EM and Neuroglancer

`viewer/ReviewViewer.js` exports `ReviewViewer({canvas,frame,status,onViewChange,onPoint,onSegmentsChange,onSave})`. The host owns durable research records. The viewer owns only bounded, evictable image caches and a per-window synchronization session.

Methods: `setTask(task,view,segments)`, `setView(view)`, `getView()`, `getSegments()`, `updateSegments(segments)`, `setOverlays(marks)`, `setTool(mode)`, `setLanguage('ru'|'en')`, `retry()`, `clearCache()`, `detach()`, `exportPlane()`, `destroy()`.

`exportNavigationFigure()` also returns `{files,metadata}` with the actual native canvas as `navigation-neuroglancer.png` and `navigation-metadata.json`. It waits for the current task/revision and loaded scene, draws the existing renderer without reconstructing its camera, and captures that canvas immediately. If a synchronized scene remains partially loaded after 15 seconds, it captures a visibly labeled partial navigation figure and records exact per-layer/panel readiness plus `sceneReady:false`. It fails if the scene is unsynchronized or changes during capture. The figure retains native viewer state and segmentation version; it is not a substitute for native raw EM evidence. Missing rendering does not imply missing anatomy.

Views are `{centerNm:[x,y,z],plane:'xy'|'xz'|'yz',spanNm:4096,resolutionNm:[8,8,40],ngState:{...}}`. `spanNm` is horizontal physical field width, clamped to a practical 512–8192 nm native plane. Navigation beyond that field is unlimited inside the public volume; Neuroglancer provides its own multiscale overview. The vertical extent is rounded to whole native samples. Wheel changes the field width, Shift+wheel steps serially, drag pans in navigation mode. In an annotation mode, a click emits `{pointNm,plane,sourceBinding,taskId}` only for loaded pixels.

Native zoom and camera orientation are retained in `ngState`. Exact orthogonal native camera orientations also select the matching raw plane. Arbitrary oblique native views remain saved as navigation views with `nativeOblique:true`; the raw evidence plane remains orthogonal and is labeled as such. A native overview can be wider than the bounded raw acquisition field. Native edits that replace a pinned source URL or coordinate scale are rejected for saved picks/navigation evidence until the task is reopened; they cannot silently rebind IDs to another source.

Marks accept `id`, `type` or `kind`, `pointsNm` (or `points`, or `pointNm`), `plane`, `color`, `visible`, `label`, `note`. Point, open trace, distance and rectangular ROI overlays are supported. Off-plane vertices are not projected onto the current plane, and lines are never drawn between off-plane vertices in a 2D evidence panel. User notes are preserved verbatim. UI editing, undo and saved evidence belong to the host.

## Coordinates and source versions

The retained preparation convention is explicit: `nm = (local + voxel_offset) * resolution`. A sample with global index `[94120,80824,21466]` is exactly `[752960,646592,858640]` nm. No +0.5 from the working site's TIFF path is applied. A pointer selects the native integer sample beneath it; annotation graphics are centered visually over that pixel. XY is horizontal X, vertical Y; XZ is X,Z; YZ is Y,Z. Neither EM nor the viewer adds resolution to the 8 × 8 × 40 nm source. The 4/4/40 annotation grid and original 16/32 nm preparation arrays are separate sources.

The public EM info is re-read on first use and rejected if its finest level is no longer raw uint8 at 8 × 8 × 40 nm. The exact metadata bytes are hashed. The focused native plane reader uses HTTP range requests for the source's existing sharded encoding and lossless gzip transport. Each decoded chunk receives a SHA-256 recorded in figure metadata. `native-source-witness.json` records a real network retrieval; raw acquisition bytes are not committed.

The native viewer uses its established multiscale/chunk engine, public `seg_m1300` segmentation and real meshes. Segmentation IDs are strings. Release661 root IDs are never inserted into public v1300 selections by the adapter. Native picks become `{id,source:'seg_m1300',identityStatus:'candidate',visible,color,label,note}`. Spatial selection does not establish a verified release661 mapping or a dendritic arbor partition. Double-click a segmentation in the native view using Neuroglancer's normal selection workflow; chosen IDs synchronize to the host list. The host can retain names and notes and toggle visibility.

## Loading and failure

Four chunks are fetched concurrently. Central chunks render first, and missing areas remain a visible checkerboard until available; a failed or out-of-bounds plane cannot export. Switching task/view aborts outstanding ranges, and a sequence guard prevents stale progress or pixels from overwriting the new task. Nearby serial sections reuse whole native chunks. Decoded imagery has a 32 MiB in-memory LRU and at most 96 persistent chunks in the distinct Cache Storage cache `dendritic-arbor-em-v2`. Image-cache failure falls back to memory and reports the issue. Review IndexedDB storage is neither opened nor deleted by this module. Metadata indexes are also bounded. Each request rejects HTTP 200 responses to a Range request instead of downloading an entire multi-gigabyte shard.

## Linked windows and evidence

`vendor/neuroglancer` contains the unchanged core assets copied from the working co-innervation website, its upstream third-party NOTICE and byte/hash manifest. The original source URL is `https://ngl.microns-explorer.org/`. Only the small v2 host page and bridge are new. Existing Native viewer construction/restore conventions informed this bridge, without bringing across the older study's case metadata, identity assumptions, storage or offset.

A random per-host BroadcastChannel session connects the embedded viewer and detached window. Session Storage retains the link when the host is reloaded. Task epochs and host revisions discard stale messages, and segment/camera edits synchronize both ways. A detached peer cannot change an obsolete task after the host switches tasks. Same-origin serving is required; opening files directly is unsupported. Ctrl+S inside Neuroglancer emits the host save request.

`exportPlane()` returns `{files:[{name,blob}],metadata}` with `raw-native.png`, `overlay.svg`, `annotated-physical.png`, `figure-metadata.json`. The raw PNG retains the native sample array with pHYs physical-pixel metadata (XZ/YZ pixels are anisotropic). The annotated PNG uses nearest-neighbour physical-aspect correction, a calibrated scale and plane/depth caption; this interpolation adds no anatomical detail. The vector file shares its physical viewBox. Metadata includes exact native dimensions, physical dimensions, source URL, info/chunk/output hashes, sample convention, panel marks/notes and selected segmentation provenance. Partial planes cannot export. Exported evidence is self-contained for the displayed region, not for unacquired 3D anatomy. The host packages these files together with the portable project records.

Sharding implementation references: [Neuroglancer sharded format](https://github.com/google/neuroglancer/blob/master/src/datasource/precomputed/sharded.md), [multiscale volume format](https://github.com/google/neuroglancer/blob/master/src/datasource/precomputed/volume.md). This small focused-plane reader is for native evidence acquisition; the native viewer retains responsibility for multiscale streaming and segmentation decoding.
