# Native EM first-visit and serial loading correction

The earlier cache correction helped already loaded chunks but did not fix first visits or chunk-boundary crossings. On 2026-10-09, a clean public-site comparison measured 17.04 seconds for the new site's initial plane versus 4.29 seconds for the original site's prepared TIFF volume. The sixth section step then stalled for 13.65 seconds when it crossed a 16-section native chunk boundary. The previous four-step warm test missed that boundary.

The original site serves prepared imagery and branches from the website. The new site instead requested 25 native EM chunks through remote shard indexes, while an invisible Neuroglancer instance fetched additional data. A diagnostic control counted 252 source requests with that hidden instance versus 55 without it; first-plane completion was 16.606 versus 7.463 seconds in those runs. These are observed runs on one connection, not timing guarantees or a controlled population benchmark.

The correction uses the same prepared-asset approach within bounded regions:

- Every task has an exact 512 × 512 native starter plane. Its 137,365–167,084 compressed bytes are fetched before the neighboring chunk packs, without waiting for public metadata. The first task's starter is 151,694 bytes.
- Fifty tasks share 36 distinct anchors and 171 deduplicated native chunk packs. Five adjacent Z slabs provide 80 sections around each anchor, including at least 32 sections in either direction. Background downloads are limited to two packs at a time and prioritize the current slab and its nearest neighbors.
- The native EM pixels remain uint8 at 8 × 8 × 40 nm, with integer sampling and no half-voxel offset, interpolation or intensity changes. Each prepared file and decoded chunk is hashed; receipts retain the original shard URL, byte range, shape, coordinates and source metadata hash. Live fallback verifies the metadata before mixing remote chunks with prepared imagery.
- The full Neuroglancer viewer starts only when needed. The main right pane independently loads one of four genuine, source-bound candidate branch meshes; see `default-branches.md`.

`viewer/raw-source.js` retains shared requests, immediate cancellation of obsolete callers, bounded live-source concurrency, cached hashes and native stride copies. Its image cache is separate from reviewer storage and bounded to 64 MiB in memory and 256 persistent chunks. Clearing that cache leaves packaged source assets and review work intact. Equivalent integer planes and 3D camera movement do not reload EM; stale planes cannot be annotated or exported as the requested new position.

`tools/prepare-em.mjs` writes only derived website assets. `tools/verify-prepared-em.mjs` independently checked all 207 compressed assets, 4,275 native chunk receipts and hashes, all 36 starter planes against their raw chunks, and all 50 tasks' ±32-section coverage. There were zero starter-pixel mismatches. Compressed imagery totals 669,479,702 bytes; the largest asset is 4,295,881 bytes. These assets are downloaded on demand, not as one site-wide transfer.

The local browser witness (`cold-start-witness.json`) records a complete first plane 439 ms after navigation, automatic branches without a native iframe, and 64 section steps covering +32 and −32 offsets at 14.7–25.9 ms, with no live-source bytes and independently matching native pixels. It also checks rapid task changes, saved work, reload and cache clearing. Synthetic source tests separately exercise all 80 sections across four chunk boundaries, corrupt assets and metadata-version changes.

The correction is now deployed at code commit `9d995624a48171dfc596794d71ab99a4bc2523de` by [run 37935498264](https://github.com/TonyTheCatMan/microns-dendritic-arbor-review/actions/runs/37935498264). The [public browser witness](live-cold-start-witness.json) passed all seven checks: a clean visit displayed the complete plane in **3.468 seconds** and automatic branches in **3.446 seconds**, compared with the earlier public runs of 17.04 seconds for this site and 4.29 seconds for the original. The source-plane operation itself took 682.2 ms and its starter transferred 151,694 bytes. These are individual public runs on the tested connection, not a repeated controlled benchmark; the 439 ms localhost result is not used for that comparison.

All 64 public section moves matched independently reconstructed native pixels, with no BossDB/GCS requests and no hidden Neuroglancer instance. Median latency was about 17.5 ms. The first move waited 749.7 ms for a nearby pack; the previously problematic sixth move took 184.7 ms. Already available moves took 15.2–24.3 ms, and the negative-direction maximum was 23.9 ms. The first anchor's 80 prepared sections span offsets −42 through +37, fully covering the ±32 test.

Wider fields, large pans, and positions outside the prepared regions still require public-source access; background packs can take time on a slow connection. Prepared navigation coverage is not a complete anatomical reconstruction or a reviewed decision.
